Автоматический DNS-сервер для Docker-контейнеров на базе CoreDNS, работающий там, где стандартный резолвер Docker (`127.0.0.11`) недоступен.

### ❓ Зачем это нужно?
В стандартном Docker контейнеры видят друг-друга по именам благодаря встроенному резолверу, который на самом деле не отдельный процесс, а цепочка правил iptables на хосте.

При использовании сторонних рантаймов (Kata или gVisor), эти правила игнорируются и удобная фича не работает.

**Этот скрипт:**
1. Подписывается на Docker Events
2. Автоматически создает DNS-записи на основе меток (labels)
3. Предоставляет Split-Horizon DNS, изолируя сети разных пользователей

### 🐸 Как использовать
1. Поднимите DNS-сервер:

```
mkdir /opt/dns-server && cd /opt/dns-server
```
```
git clone git@github.com:staxxy403/ctrlfree-dns-discovery.git .
```
```
docker compose up -d
```
---
При запуске контейнеров с user-defined сетями, Docker ВСЕГДА прокидывает свой `127.0.0.11` внутрь, даже если указать флаг `--dns`. Нужно определить резолвер вручную.

2. Создайте файл `/etc/docker-resolv.conf` и укажите IP вашей машины:
```
nameserver 10.50.11.11
```

3. Добавьте метку `custom_dns` к контейнеру при запуске:
```
docker run -d \
    -v /etc/docker-resolv.conf:/etc/resolv.conf \
    --label "custom_dns=api" \
    --network "user-123-network" \
    my-api
```
Теперь любой контейнер в этой сети сможет достучаться до этого по имени `api`.

### 🛡 Важно!

**Скрипт писался под работу внутри VM/LXC.** Если запускаете на машине с публичным IP:
- Никогда не открывайте 53/udp наружу
- Настройте фаервол, чтобы он разрешал запросы только из приватных сетей на этот порт
